예전엔 JavaScript로 하던 일, 이제는 CSS로

상태를 감지하고, 요소의 위치를 계산하고, 스크롤에 맞춰 애니메이션을 재생하던 코드가 점점 CSS로 옮겨가고 있습니다.
이번 달에는 JavaScript 의존도를 줄여 주는 CSS 기능 9가지를 실무 활용 관점에서 살펴봅니다.

:HAS() · BASELINE 2023

부모 찾기와 상태 반영은 :has()

자식 요소의 상태에 따라 부모나 앞선 형제를 꾸밉니다. 체크된 입력을 포함한 카드, 오류가 있는 폼, 열린 메뉴를 찾으려고 클래스를 추가하던 코드를 줄일 수 있습니다.
CONTAINER QUERY · BASELINE 2023

컴포넌트 반응형은 컨테이너 쿼리로

ResizeObserver로 너비를 읽어 클래스를 바꾸는 대신, 컴포넌트가 놓인 컨테이너 크기에 맞춰 레이아웃을 전환합니다. 재사용 카드와 사이드바에 특히 유용합니다.
ANCHOR POSITIONING · 지원 확인

툴팁 좌표 계산은 앵커 포지셔닝으로

getBoundingClientRect()로 기준 요소의 좌표를 구하지 않고 팝오버와 툴팁을 배치합니다. 공간이 부족할 때 브라우저가 시도할 대체 위치도 지정할 수 있습니다.
SCROLL-DRIVEN ANIMATION · 지원 확인

스크롤 진행률을 애니메이션 타임라인으로

scroll 이벤트에서 진행률을 계산하지 않고 animation-timeline: scroll() 또는 view()를 사용합니다. 읽기 진행 표시와 등장 효과를 매끄럽게 연결할 수 있습니다.
SCROLL-STATE QUERY · 지원 확인

sticky 상태와 스냅 위치 감지하기

IntersectionObserver나 스크롤 위치 비교 없이 붙어 있는 헤더와 스냅된 항목을 선택합니다. 캐러셀의 현재 카드나 고정 헤더의 그림자를 CSS만으로 표현할 수 있습니다.
@STARTING-STYLE · BASELINE 2024

display: none도 자연스럽게 전환하기

@starting-style과 transition-behavior: allow-discrete를 조합해 팝오버와 dialog의 등장·퇴장 효과를 만듭니다. 애니메이션용 클래스를 넣고 빼는 코드를 줄여 줍니다.
INTERPOLATE-SIZE · 지원 확인

height: auto 전환도 CSS로

콘텐츠 높이를 측정해 픽셀 값으로 넣는 대신 interpolate-size: allow-keywords 또는 calc-size()로 auto 크기를 전환합니다. 아코디언과 펼침 패널에 활용해 보세요.
CSS CAROUSEL · CHROME 135+

버튼과 인디케이터가 있는 CSS 캐러셀

::scroll-button과 ::scroll-marker로 탐색 버튼과 페이지 표시를 생성합니다. 브라우저 지원이 제한적이므로 scroll-snap 기반 레이아웃을 기본 경험으로 남겨 두세요.

React 코드 추천

화면 전환과 폼처럼 퍼블리싱 작업에 바로 연결되는 React 구현을 골랐습니다.

<ViewTransition>으로 화면 전환 연결하기

컴포넌트의 등장·퇴장·업데이트를 브라우저 View Transition과 연결합니다. React가 전환 시점과 이름을 조율하므로, 페이지 이동이나 목록 변화에 CSS 전환 클래스를 적용하는 구조를 단순하게 만들 수 있습니다.

<Activity>로 숨긴 폼의 상태 유지하기

보이지 않는 UI를 완전히 제거하지 않고 상태를 보존하면서 숨깁니다. 탭 패널이나 단계형 폼을 다시 열었을 때 입력값을 유지할 수 있으며, React Hook Form 7.85부터 Activity 경계 안의 폼도 지원합니다.

Questionnaire로 다단계 질문 폼 구성하기

shadcn React의 Questionnaire 패턴은 단일·복수 선택, 직접 입력, 건너뛰기, 유효성 검사와 이전·다음 이동을 조합합니다. 온보딩이나 설문 UI에서 의미 있는 폼 구조와 키보드 조작을 설계할 때 참고하기 좋습니다.
