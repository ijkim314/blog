접근성 구현의 변화부터 AI Pro 사용 후기까지

9월은 오랜만에 코딩에 푹 몰두했던 한 달이었습니다.
이번 달에는 퍼블리셔가 알아두면 좋을 접근성 구현 방법을 소개하고, 최근 참여한 프로젝트에서 사용한 AI Pro의 후기를 정리했습니다.

01 · 모달과 팝오버, HTML로 제어하기

열고 닫는 동작부터 포커스까지, 브라우저의 기본 기능을 활용합니다.

DIALOG · 브라우저 지원 확인

모달 닫기, 이제 HTML 속성으로

closedby 속성의 any·closerequest·none 값으로 모달 바깥 클릭이나 Esc 키를 통한 닫기 동작을 제어합니다. showModal()로 연 모달의 초기 포커스 위치와 닫은 뒤 포커스가 돌아가는 위치도 확인하세요.
COMMAND · 브라우저 지원 확인

버튼과 모달을 연결하는 commandfor

button의 commandfor 속성으로 대상을 지정하고, command 속성의 show-modal·close 값으로 모달을 열고 닫습니다. 제어 코드를 줄일 수 있으며, 대화상자의 접근 가능한 이름과 포커스 이동도 함께 점검해야 합니다.
POPOVER HINT · 브라우저 지원 확인

열린 메뉴를 유지하며 도움말 띄우기

popover="hint"로 기존 auto 팝오버를 닫지 않고 보조 설명을 표시합니다. 팝오버를 표시하는 것만으로 툴팁이나 메뉴의 접근성이 갖춰지지는 않으므로, 요소의 역할과 키보드 동작도 함께 설계하세요.

02 · 커스텀 UI에서도 기본 접근성 유지하기

디자인을 확장하면서 네이티브 요소의 조작 방식과 의미를 지킵니다.

CUSTOM SELECT · 브라우저 지원 확인

직접 꾸미는 네이티브 셀렉트

select와 selectedcontent, appearance: base-select로 선택 영역과 옵션을 꾸밉니다. 기본 키보드 동작을 활용하고, 아이콘 중심 디자인에서도 선택 항목을 식별할 수 있는 텍스트를 유지하세요.
DETAILS NAME · 실무 활용

하나만 열리는 아코디언, name으로 묶기

details 요소에 같은 name 값을 지정하면 한 항목을 열 때 다른 항목이 닫힙니다. summary의 키보드 조작을 활용하고, 비교가 필요한 내용에는 여러 항목을 펼칠 수 있게 구성하세요.
INERT · 실무 활용

닫힌 패널에 포커스가 들어가지 않게

inert로 비활성 영역을 탭 순서와 접근성 트리에서 제외합니다. aria-hidden만으로는 키보드 포커스를 막을 수 없습니다. 패널을 닫을 때 해당 패널을 열었던 버튼으로 포커스가 돌아가는지도 확인하세요.

03 · 2026년 주목할 HTML 접근성 기능

새로 도입되거나 실험 중인 기능을 살펴보고, 미지원 환경의 대안도 준비합니다.

FOCUSGROUP · CHROME 150

방향키 탐색도 HTML 속성으로

focusgroup으로 툴바·탭 목록의 방향키 탐색과 마지막 포커스 위치 기억을 설정합니다. Chrome 150에 소개된 기능으로, 탭 선택 상태와 패널 전환 로직은 별도로 구현해야 합니다.
INTERESTFOR · 실험적·비표준

마우스와 키보드로 확인하는 도움말

interestfor로 hover·focus 등 사용자의 관심 동작에 반응하는 팝오버를 연결합니다. 마우스 전용 도움말을 개선하는 실험적 기능으로, 미지원 환경에서도 설명에 접근할 방법이 필요합니다.
HEADING OFFSET · 실험적

컴포넌트의 제목 수준 조절하기

headingoffset과 headingreset으로 보조 기술에 전달되는 제목 수준을 조절합니다. 화면에 보이는 크기는 바뀌지 않으며, 미지원 브라우저에서도 제목 구조를 이해할 수 있도록 기본 제목 태그의 계층을 구성해야 합니다.

2026년 9월 기준 · 기본 태그와 새 속성의 지원 범위는 다를 수 있습니다. 대상 브라우저의 지원 여부를 확인하고, 키보드와 스크린 리더로 실제 동작을 점검하세요. 이 기능들은 웹페이지를 구현할 때 활용할 수 있습니다.

AI Pro 사용 후기

최근 우리은행 AI 에이전트 구축 프로젝트에 참여하면서 삼성SDS의 AI Pro를 사용해 보았습니다. 프로젝트 환경에 설치된 VS Code 확장 프로그램을 통해 실제 작업에 활용했습니다. 빠듯한 일정 속에서 화면을 구현해야 했던 만큼, AI Pro가 작업에 얼마나 도움이 될지 궁금했습니다.

삼성SDS는 AI Pro를 IT 개발·운영 업무를 위한 코드 어시스턴트로 소개합니다. 쉽게 말하면 코드를 다루는 일을 돕는 AI 도구입니다. 삼성SDS 공식 소개를 참고해, 이번 프로젝트에서 활용한 방식과 퍼블리셔로서 느낀 점을 정리해 보았습니다.

AI가 작업하는 동안, 저는 화면을 만들었습니다

AI Pro에 작업 요청을 입력한 뒤 결과를 받기까지는 시간이 조금 걸렸습니다. 그래서 답변이 나올 때까지 기다리기보다, 자료 검색이 많이 필요한 작업을 AI Pro에 맡기고 그동안 저는 화면을 구현했습니다.

혼자 진행했다면 검색하고 내용을 살펴보느라 화면 작업을 잠시 멈춰야 했을 텐데, AI Pro와 작업을 나누니 화면 구현을 이어 갈 수 있었습니다. 응답을 기다리는 시간을 활용할 수 있어 빠듯한 일정을 맞추는 데 도움이 되었습니다.

질문을 구체적으로 정리하는 과정도 중요합니다

예를 들어 아코디언 메뉴를 수정한다면 “이 코드를 고쳐줘”라는 말만으로는 원하는 결과를 설명하기 어렵습니다. 어떤 동작을 기대하는지, 무엇을 유지해야 하는지 함께 적으면 작업의 방향이 더 명확해집니다. 다음은 이런 상황에서 활용할 수 있는 질문 예시입니다.

“이 아코디언 코드가 어떻게 동작하는지 쉽게 설명해 줘. 기존 디자인은 유지하면서 키보드로도 열고 닫을 수 있게 바꾸려고 해. 바로 수정하기 전에 바꿔야 할 부분과 이유부터 알려줘.”

설명을 읽고, 수정 방향을 정하고, 필요한 부분부터 적용하는 순서입니다. 이렇게 질문을 준비하다 보면 저 역시 무엇을 해결하려는지 다시 정리하게 됩니다. 질문을 구체화하는 과정은 작업 조건을 분명히 하는 데에도 도움이 됩니다.

도움이 되었던 점, 그리고 직접 확인할 부분

이번 경험에서 가장 유용했던 활용법은 자료 검색과 화면 구현을 병행하는 것이었습니다. 응답 속도는 아쉬웠지만, 요청할 작업과 직접 할 작업을 미리 나누어 두면 기다리는 시간을 활용할 수 있었습니다.

한편 제안받은 코드를 읽고 검토하는 과정은 여전히 필요합니다. 프로젝트의 코드 작성 규칙에 맞는지, 모바일 화면에서 배치가 자연스러운지, 키보드로 조작할 수 있는지 직접 확인해야 합니다. 기존 기능에 영향을 주지 않는지도 살펴봐야 하고요. AI가 제안한 코드는 실제 화면에서 동작을 확인하는 단계까지 마쳐야 작업이 완료된다고 생각합니다.
