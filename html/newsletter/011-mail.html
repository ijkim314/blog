아직 100%는 아니지만, 지금 주목할 웹 코드

모든 브라우저에서 안심하고 쓰기에는 이르지만, 웹 개발의 다음 기본값이 될 기능들이 빠르게 등장하고 있습니다.
이번 달에는 폴백과 기능 감지를 곁들이며 미리 실험해 볼 HTML·CSS·JavaScript 기능 8가지를 골랐습니다.

HTML · CUSTOMIZABLE SELECT

네이티브 select를 원하는 모습으로

appearance: base-select와 <selectedcontent>로 옵션에 아이콘과 레이아웃을 넣습니다. 기존 select 의미와 키보드 조작을 유지하면서 커스텀 UI를 만들 수 있습니다.
HTML · INTEREST INVOKERS

툴팁을 여는 interestfor

interestfor 속성으로 hover와 키보드 포커스에 반응하는 팝오버를 선언합니다. 지연 시간도 CSS로 조절해 툴팁 이벤트 코드를 크게 줄일 수 있습니다.
CSS · IF()

조건문을 CSS 속성 값 안으로

if(style(), media(), supports())로 조건에 맞는 속성 값을 고릅니다. 같은 선언을 여러 규칙에 반복하지 않고 한곳에서 테마와 기능 지원을 분기할 수 있습니다.
CSS · SIBLING-INDEX()

형제 순서와 개수를 CSS에서 계산하기

sibling-index()와 sibling-count()로 목록의 순번과 전체 개수를 얻습니다. nth-child 반복이나 인라인 변수를 만들지 않고 지연·색상·배치를 계산합니다.
CSS · SCROLL-TRIGGERED

IntersectionObserver 없이 등장 효과

timeline-trigger와 animation-trigger로 요소가 특정 스크롤 경계를 지날 때 시간 기반 애니메이션을 재생합니다. 아직은 IntersectionObserver 폴백이 필요합니다.
JAVASCRIPT · TEMPORAL

Date의 오래된 함정을 벗어나는 Temporal

Temporal.PlainDate와 ZonedDateTime으로 날짜, 시간대, 기간 계산을 명확히 분리합니다. 네이티브 지원 전에는 공식 폴리필로 API를 먼저 익혀 볼 만합니다.
JAVASCRIPT · USING

using으로 리소스 정리를 자동화하기

using과 await using은 블록을 벗어날 때 Symbol.dispose를 호출합니다. 파일·락·연결처럼 반드시 닫아야 하는 리소스의 try/finally 중첩을 줄여 줍니다.
JAVASCRIPT · ITERATOR HELPERS

이터레이터도 map·filter·take로

Iterator.map(), filter(), take()는 중간 배열 없이 값을 지연 처리합니다. 최신 브라우저에는 들어왔지만 구형 환경을 고려해 빌드 타깃과 폴리필을 확인하세요.

같은 색도 다르게 이어집니다, CSS 그라디언트와 색 공간

그라디언트를 만들 때는 시작 색과 끝 색만 고르면 된다고 생각하기 쉽습니다. 하지만 두 색 사이를 어떤 색 공간에서 계산하느냐에 따라 중간 색은 꽤 다르게 보입니다. 기본값인 sRGB에서는 색이 중간에서 탁해질 수 있고, OKLCH에서는 예상하지 못한 밝은 색조를 지나갈 수도 있습니다. 어느 쪽이 늘 더 좋다기보다 화면의 의도에 맞는 경로를 고르는 일이 중요합니다.

그라디언트의 색 공간을 직접 지정해 보기

CSS 그라디언트에는 in oklch처럼 보간할 색 공간을 지정할 수 있습니다. 예를 들어 linear-gradient(in oklch, red, blue)는 두 색 사이를 OKLCH에서 계산합니다. Keith Grant의 그라디언트 색 공간 가이드는 같은 색 조합이 공간에 따라 어떻게 달라지는지 비교하기 좋습니다.

선택지는 srgb, srgb-linear, display-p3, oklab, oklch, xyz 등 다양합니다. 넓은 색 영역이 필요하다고 무조건 자연스러운 결과가 나오는 것은 아닙니다. 브랜드 색이나 상태 색처럼 정확한 인상이 중요한 경우에는 실제 그라디언트를 여러 화면에서 비교하고 필요한 위치에 중간 색상점을 추가하는 편이 안전합니다.

OKLCH가 다루기 편한 이유

OKLCH는 밝기, 채도, 색조를 사람이 느끼는 차이에 가깝게 다루도록 설계된 색 모델입니다. 같은 밝기 값을 사용한 서로 다른 색조가 비교적 비슷한 밝기로 느껴져, 테마나 상태별 색상군을 만들 때 결과를 예측하기 쉽습니다. Jakub Krehel의 OKLCH 설명도 색을 코드로 조절할 때 왜 이런 특성이 유용한지 이해하는 데 도움이 됩니다.

익숙한 hsl()도 색조·채도·밝기를 나눠 다룰 수 있지만 기반 색 공간은 sRGB로 고정됩니다. oklch()는 비슷한 방식으로 값을 조절하면서 더 넓은 색 영역을 사용할 수 있다는 장점이 있습니다. 다만 넓은 색 영역 밖의 값이나 브라우저별 표현 차이를 고려해 핵심 텍스트와 UI 상태에는 충분한 대비가 유지되는지 함께 확인해야 합니다.

색조가 지나가는 방향도 선택할 수 있습니다

원형으로 이어지는 색조는 같은 두 색 사이에도 두 방향이 존재합니다. CSS는 기본적으로 짧은 경로를 택하지만 shorter hue, longer hue, increasing hue, decreasing hue를 사용해 방향을 바꿀 수 있습니다. conic-gradient(in oklch longer hue, red, red)처럼 같은 빨강에서 시작하고 끝내도 긴 경로를 지정하면 색상환 전체를 지나는 그라디언트를 만들 수 있습니다.

conic-gradient의 중심점을 옮기고 색상점을 같은 위치에 겹쳐 단단한 경계를 만들면 삼각형이나 부채꼴 같은 형태도 그릴 수 있습니다. 단순한 배경 효과를 넘어 차트, 컬러 피커, 각도 기반 장식처럼 방향성이 필요한 UI에 활용할 수 있지만, 복잡한 색 변화가 정보 전달을 방해하지 않는지도 살펴봐야 합니다.

색상 도구는 결과보다 판단을 돕는 용도로

직접 여러 색 공간과 색상점을 조합하기 어렵다면 ColorFlow 같은 메시 그라디언트 생성기를 출발점으로 사용할 수 있습니다. 여러 색의 위치와 혼합 결과를 빠르게 탐색하고, 마음에 드는 결과를 프로젝트의 토큰과 CSS로 옮기는 방식입니다.

팔레트 생성기는 완성된 답을 대신 정해 주기보다 선택지를 비교하는 도구에 가깝습니다. 브랜드의 분위기, 배경과 글자의 대비, 라이트·다크 테마에서의 변화까지 확인한 뒤 최종 색을 다듬어야 합니다. 특히 그라디언트는 양 끝의 색만 검사하지 말고 중간에 의도하지 않은 탁한 색이나 지나치게 밝은 색이 생기지 않는지 확인해 보세요.
