Kim's Focus

눈으로 하던 퍼블리싱 QA를 자동화하기까지

유경표 본부장님 요청으로 사이트 제작에 대한 리뷰를 간단히 적어 보았습니다.

퍼블리싱 작업을 하면서 디자인 시안과 실제 결과물을 자동으로 비교하는 QA 도구를 만들어보고 싶었습니다. 하지만 개발적인 부분이 많아 쉽게 시도하지 못하다가 AI 도구가 활성화되면서 작업을 시작하게 되었습니다. 이번 작업은 제가 직접 코드를 작성하기보다 Claude Code를 활용해 개발을 진행했습니다.

디자인 시안과 퍼블리싱 결과물을 사람이 일일이 비교하는 일은 개인적으로 꽤 큰 작업이었고, 많은 시간을 잡아먹었습니다. 작은 차이를 놓치지 않으려면 두 화면을 계속 번갈아 확인해야 했고, 화면이 많아질수록 검수 시간도 크게 늘어났습니다. 이 반복적인 작업을 줄여보고자 처음에는 개인적으로만 사용할 목적으로 QA 도구를 만들기 시작했습니다.

AI에게 처음부터 복잡한 내용이나 많은 양의 작업을 한꺼번에 지시하지는 않았습니다. 먼저 전체적인 목표를 정한 뒤, 필요한 기능을 한 가지씩 질문하고 진행했습니다. 한 번에 너무 많은 결과를 받으면 내용을 제대로 이해하지 못한 채 넘어갈 수 있고, 저 역시 작업을 어느 정도 이해하면서 진행해야 처음 목표한 방향에서 벗어나지 않는다고 생각했기 때문입니다.

최초 버전은 기능이 거의 없는 상태였습니다. 내부 TypeScript 파일의 배열에 비교할 내용을 직접 입력한 뒤 npm run qa 명령어를 실행하면 해당 내용만 리포트 형태로 받아보는 방식이었습니다. 실제 작업에 적용해 보니 예상보다 비교 결과가 좋아, 혼자 사용하는 데서 그치지 않고 팀원들과도 공유하면 좋겠다는 생각이 들었습니다. 그래서 별도의 개발 환경을 준비하지 않아도 누구나 결과를 확인하고 사용할 수 있도록 GitHub에 공개된 웹사이트 형태로 발전시키기로 했습니다.

이후 사용자가 비교할 주소와 화면 정보를 직접 입력하고, 디자인 이미지를 업로드하고, 토큰을 입력한 사용자만 실행할 수 있도록 제한하는 기능까지 세부 기능을 하나씩 추가했습니다. 이때도 AI에게 곧바로 코드를 수정하도록 요청하기보다 먼저 어떤 방식으로 작업할지 의견을 달라고 한 뒤, 방향을 이해하고 나서 실제 작업을 요청했습니다. 바로 수정부터 진행했을 때 오류가 발생하거나 불필요한 작업이 포함되면 원래 상태로 되돌리는 과정이 오히려 더 번거로웠기 때문입니다.

먼저 기존 기능이 로컬 환경에서 안정적으로 동작하도록 작업하고 충분히 테스트한 뒤, 같은 QA 기능을 웹 환경에서도 실행할 수 있도록 추가 개발을 진행했습니다. 현재는 목적에 따라 다음과 같이 사용할 수 있습니다.

1. 비교 결과를 정적인 리포트로 생성 npm run qa
2. 로컬 환경에서 직접 QA를 실행 npm run qa:dev
3. 브라우저에서 QA를 실행하고 결과 확인

로컬 버전과 웹 버전은 실행 환경과 필요한 설정이 서로 달랐기 때문에 작업 브랜치도 local과 dev로 분리했습니다. 각 환경의 변경 사항이 서로 섞이거나 충돌하는 것을 줄이고, 기능을 독립적으로 테스트하기 위한 선택이었습니다. 덕분에 기존 로컬 방식은 그대로 유지하면서 웹 환경에 필요한 기능을 별도로 확장할 수 있었습니다.

처음에는 개인적인 불편을 해결하기 위해 시작한 작은 도구였지만, 실제 비교 결과를 확인하면서 팀원들과 함께 사용할 수 있는 형태로 발전하게 되었습니다. 앞으로도 로컬과 웹 환경에서 발견되는 불편을 하나씩 개선하며, 반복되는 퍼블리싱 QA 작업에 드는 시간을 줄여나갈 생각입니다.

작은 기준의 차이가 결과를 바꿉니다. 다음 뉴스레터에서 다시 뵙겠습니다.
